Source sets & dependencies소스셋과 의존성

Tell the plugin where your Python lives and what it depends on.

Python 코드가 어디 있고 무엇에 의존하는지 플러그인에 알려줍니다.

Where the package is패키지 위치

python {
    sourceSets {
        val commonMain by getting {
            srcDirs("src/commonMain/python")          // the pypackpack package
            metaDirs("src/commonMain/generated/meta") // .pyi stubs, merged into the bundle
            libDirs("src/commonMain/build/site-packages")
        }
    }
}
Rule규칙Detail내용
Package directory패키지 디렉터리localLibraryPath if set, otherwise the first commonMain.srcDirs entry, otherwise none (install and bundle skip).localLibraryPath 가 있으면 그것, 없으면 commonMain.srcDirs 의 첫 항목, 그것도 없으면 없음 (설치와 번들 건너뜀).
metaDirs, libDirsmetaDirs, libDirsEvery entry is forwarded to pypackpack's BundleRequest.모든 항목이 pypackpack 의 BundleRequest 로 전달됩니다.
Only on commonMaincommonMain 에서만The three directory functions throw in any other source set.세 디렉터리 함수는 다른 소스셋에서 호출하면 예외가 납니다.

Dependencies의존성

python {
    sourceSets {
        val commonMain by getting {
            dependencies {
                implementation("pyzmq")
                implementation("rpds-py==0.20.0")
            }
        }
        val androidMain by getting {
            dependencies {
                integration("pycomposeui")   // a Python package that depends on Kotlin
            }
        }
    }
}

installPythonDependencies runs a real uv add in the package directory through pypackpack's uv backend, so the result is recorded in your pyproject.toml.

installPythonDependencies 는 pypackpack 의 uv 백엔드를 통해 패키지 디렉터리에서 실제 uv add 를 실행하므로, 결과가 pyproject.toml 에 기록됩니다.

Two limits today. Every source set's dependencies are installed into one list, so an androidMain dependency is installed for every target. And integration() installs exactly like implementation(): the KLIBDEPENS wheel check the DSL describes is not implemented yet.

지금의 한계 두 가지. 모든 소스셋의 의존성이 하나의 목록으로 설치되므로 androidMain 의존성도 모든 타깃에 설치됩니다. 그리고 integration() 은 implementation() 과 똑같이 설치됩니다. DSL 이 설명하는 KLIBDEPENS 휠 검사는 아직 없습니다.

Package repositories패키지 저장소

python {
    defaultConfig {
        pip {
            autoUpdate = true                                  // uv add --upgrade
            repositories {
                central { setUrl("https://mirror.example/simple") }  // --default-index
                local { url = Paths.get("wheels").toUri().toString() } // --find-links
            }
        }
    }
}

central's first URL replaces PyPI; any further URLs are added as extra indexes. local is a directory of wheels. jit { } (building packages from recipes) is not supported yet: declaring it fails installPythonDependencies with the reason, and only when there is something to install.

central 의 첫 URL 이 PyPI 를 대신하고, 나머지 URL 은 추가 인덱스가 됩니다. local 은 wheel 이 든 디렉터리입니다. jit { }(레시피로 패키지 빌드)는 아직 지원하지 않습니다. 선언하면 설치할 것이 있을 때만 installPythonDependencies 가 이유와 함께 실패합니다.
